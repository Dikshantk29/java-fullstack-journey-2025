### ⚡ Generics — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- A feature enabling types (classes/interfaces) to be parameters when defining classes, interfaces, and methods.
- Exists to provide stronger type checks at compile-time and eliminate the need for explicit casting.
- Key purpose: To write type-safe, reusable code (e.g., Collections API) and avoid `ClassCastException`.

#### 2️⃣ Must-Remember Points
- Generics are **compile-time** concept (type erasure occurs at runtime).
- Cannot use primitives as type parameters (use `Integer`, not `int`).
- Cannot create instances of type parameter (`new T()` is invalid).
- Cannot declare `static` fields of a class's type parameter.
- `List<String>` is a subtype of `List` (raw type), but **not** a subtype of `List<Object>`.
- `?` is a wildcard representing an unknown type.
- `extends` keyword is used for both classes (single) and interfaces (multiple) in bounds.
- Type parameters are conventionally single uppercase letters (`T`, `E`, `K`, `V`).

#### 3️⃣ Key Code Patterns (Java)
```java
// Generic Class
class Box<T> {
    private T value;
    public void set(T val) { this.value = val; }
    public T get() { return value; }
}
// Generic Method
public <T> void printArray(T[] array) {
    for (T elem : array) System.out.println(elem);
}
// Bounded Type Parameter
public <T extends Number> void process(T num) { }
// Wildcard in parameter
public void printList(List<?> list) { }
```

#### 4️⃣ Internals / Behind the Scenes
- **Type Erasure**: Compiler replaces all type parameters with their bounds or `Object`, and inserts necessary casts.
- `List<String>` and `List<Integer>` become the same raw type `List` at runtime.
- Bridge methods are generated by compiler to maintain polymorphism with generic types.
- Instanceof checks with parameterized types (`list instanceof List<String>`) are illegal due to erasure.

#### 5️⃣ Common Interview Traps
- Assuming `List<Dog>` is a subtype of `List<Animal>` (it's not; use `List<? extends Animal>`).
- Trying to create a generic array (`new T[10]`).
- Using wildcards in return types of methods (can lead to capture errors).
- Mixing raw types and generic types leads to unchecked warnings.
- Forgetting that `ClassCastException` can still occur with improper casts from raw types.

#### 6️⃣ Interview Q&A (High Yield)
- **Q: Why are generics used?** A: For type safety and to eliminate casting, making code cleaner and less error-prone.
- **Q: What is type erasure?** A: The process by which the compiler removes all generic type information, replacing it with bounds or Object, at compile time.
- **Q: Can you have `List<int>`?** A: No, type arguments must be reference types. Use wrapper `Integer` or Java's specialized collections.
- **Q: Difference between `List<?>` and `List<Object>`?** A: `List<?>` is a list of unknown type (can be read from, cannot be added to except `null`). `List<Object>` is a list that can hold any Object type.
- **Q: PECS stands for?** A: Producer Extends, Consumer Super. Use `? extends T` when you get (produce) items, `? super T` when you put (consume) items.
- **Q: What is a bounded wildcard?** A: A wildcard with a restriction, e.g., `? extends Number` (unknown subtype of Number) or `? super Integer` (unknown supertype of Integer).
- **Q: Can a generic class extend `Throwable`?** A: No. Generic classes cannot extend `Throwable` (so no `class MyException<T> extends Exception`).

### ⚡ Introduction to Generics — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- Pre-Java 5, collections stored `Object`, requiring explicit casting and risking runtime `ClassCastException`.
- Generics allow you to specify the type of objects a collection can contain.
- It's a blueprint for creating type-safe containers and algorithms.

#### 2️⃣ Must-Remember Points
- Introduced in Java 5 (J2SE 5.0).
- Provides compile-time type safety.
- Enables more readable and maintainable code.
- Backward compatibility maintained via raw types.

#### 3️⃣ Key Code Patterns (Java)
```java
// Old way (pre-generics) - unsafe
List list = new ArrayList();
list.add("hello");
String s = (String) list.get(0); // cast needed

// With Generics - type-safe
List<String> genericList = new ArrayList<>();
genericList.add("hello");
String s = genericList.get(0); // no cast
```

#### 4️⃣ Internals / Behind the Scenes
- Raw types exist for backward compatibility but generate compiler warnings.
- The compiled bytecode for generic and non-generic code is essentially identical after erasure.

#### 5️⃣ Common Interview Traps
- Thinking generics provide runtime type information (they don't).
- Assuming you can overload methods based only on type parameters (you can't due to erasure).

#### 6️⃣ Interview Q&A (High Yield)
- **Q: Main problem generics solve?** A: Eliminating explicit casting and reducing `ClassCastException` at runtime by moving type checking to compile-time.
- **Q: Are generics covariant?** A: No, generic types are invariant by default (e.g., `List<String>` is not a subtype of `List<Object>`).

### ⚡ Benefits of Generics — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- Enhance program stability by catching type mismatches at compile time.
- Eliminate the need for explicit type casting, reducing boilerplate.
- Enable algorithms and data structures to be written once and reused for different types.

#### 2️⃣ Must-Remember Points
- **Type Safety**: Prevents `ClassCastException`.
- **Code Reusability**: Write once, use with many types.
- **Cleaner Code**: No explicit casts; intent is clear.
- **Stronger Compile-Time Checks**: Errors caught earlier.

#### 3️⃣ Key Code Patterns (Java)
```java
// Reusable generic method
public static <T> T getFirst(List<T> list) {
    return list.get(0); // Returns T, no cast
}
```

#### 5️⃣ Common Interview Traps
- Overusing generics where simple types would suffice, adding unnecessary complexity.

#### 6️⃣ Interview Q&A (High Yield)
- **Q: Biggest benefit of generics?** A: Compile-time type safety, moving runtime casting errors to compile-time errors.
- **Q: Do generics improve performance?** A: Not directly, but they reduce the need for runtime casts, which is a minor optimization.

### ⚡ Generic Syntax — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- Type parameters are declared in angle brackets `<>`.
- Used with class/interface declarations, constructor invocations, and method declarations.
- The same syntax applies for defining and using generic types.

#### 2️⃣ Must-Remember Points
- Place type parameters before class name: `class Name<T> {...}`.
- For multiple type parameters: `class Pair<K, V> {...}`.
- Diamond operator `<>` (Java 7+) allows type inference on RHS: `new ArrayList<>()`.
- Type parameters can be bounded: `<T extends Number & Comparable>`.

#### 3️⃣ Key Code Patterns (Java)
```java
// Class with multiple type parameters
class Entry<K, V> {
    private K key;
    private V value;
}
// Constructor invocation with diamond
Map<String, Integer> map = new HashMap<>();
// Bounded type parameter with multiple bounds (class first, then interfaces)
class Processor<T extends Number & Comparable<T> & Serializable> { }
```

#### 5️⃣ Common Interview Traps
- Forgetting the diamond `<>` leads to raw type usage and warnings.
- Placing bounds in the wrong order (class must be first).

#### 6️⃣ Interview Q&A (High Yield)
- **Q: What is the diamond operator?** A: `<>` introduced in Java 7, allows the compiler to infer the generic type from the left-hand side declaration.
- **Q: Can a type parameter have multiple bounds?** A: Yes, but only one can be a class, and it must come first: `T extends Class & Interface1 & Interface2`.

### ⚡ Generic Classes & Interfaces — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- A class/interface that is parameterized over types.
- Allows the same class definition to be used with different data types.
- Common examples: `ArrayList<E>`, `Comparable<T>`, `Comparator<T>`.

#### 2️⃣ Must-Remember Points
- The type parameter `T` can be used throughout the class as a field type, method return type, or parameter type.
- You can have generic constructors (rare).
- A non-static inner class can use the type parameters of its outer generic class.
- Interfaces like `Comparable<T>` are generic.

#### 3️⃣ Key Code Patterns (Java)
```java
// Generic Interface
interface Repository<T> {
    T findById(int id);
    void save(T obj);
}
// Implementing a generic interface
class UserRepository implements Repository<User> {
    public User findById(int id) { ... }
    public void save(User obj) { ... }
}
// Generic class with type parameter used in method
class Container<T> {
    private T item;
    public boolean isEmpty() { return item == null; }
}
```

#### 5️⃣ Common Interview Traps
- Trying to use `instanceof` with a generic type parameter (`obj instanceof T`).
- Instantiating the type parameter (`new T()`).

#### 6️⃣ Interview Q&A (High Yield)
- **Q: Can a class be generic and also extend a generic class?** A: Yes, e.g., `class MyList<T> extends ArrayList<T> {...}`.
- **Q: Is `java.lang.Class` generic?** A: Yes, `Class<T>`; used for reflection with type safety.

### ⚡ Upper Bounds (extends) — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- Restricts a type parameter to be a subtype of a specific class or implementer of an interface.
- Keyword `extends` is used for both classes and interfaces in this context.
- Allows you to call methods of the bound type on instances of the type parameter.

#### 2️⃣ Must-Remember Points
- Syntax: `<T extends UpperBoundType>`.
- `T` can be the bound type or any of its subclasses.
- For multiple bounds, use `&`: `<T extends ClassA & InterfaceB>`.
- The bound can be a concrete class, abstract class, or interface.

#### 3️⃣ Key Code Patterns (Java)
```java
// Upper bound with class
public <T extends Number> double sum(List<T> numbers) {
    double total = 0.0;
    for (T num : numbers) total += num.doubleValue(); // Can call Number methods
    return total;
}
// Upper bound with interface
public <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) > 0 ? a : b;
}
```

#### 5️⃣ Common Interview Traps
- Using `super` keyword in type parameter declaration (invalid: `<T super MyClass>` is not allowed for type parameters, only for wildcards).

#### 6️⃣ Interview Q&A (High Yield)
- **Q: What does `<T extends Number>` mean?** A: `T` can be `Number` or any subclass of `Number` (e.g., `Integer`, `Double`).
- **Q: Can you have `extends` for a type parameter with a final class like `String`?** A: Yes, but it's pointless as `T` could only be `String`.

### ⚡ Lower Bounds (super) — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- Used **only with wildcards** (`? super T`), not with type parameter declarations.
- Restricts the unknown type to be a supertype of a specific type.
- Enables safe writing/insertion of objects into a generic structure (Consumer).

#### 2️⃣ Must-Remember Points
- Syntax: `? super LowerBound`.
- You can **add** objects of type `LowerBound` or its subtypes to such a collection.
- You cannot safely read specific types from it (only `Object`).
- Core principle of **PECS** (Consumer uses `super`).

#### 3️⃣ Key Code Patterns (Java)
```java
// Method that consumes items into a collection
public void addNumbers(List<? super Integer> list) {
    for (int i = 1; i <= 10; i++) {
        list.add(i); // Can add Integer, because ? is supertype of Integer
    }
    // Integer value = list.get(0); // COMPILE ERROR - can't guarantee type
    Object obj = list.get(0); // Only safe to read as Object
}
```

#### 5️⃣ Common Interview Traps
- Trying to use `super` in a class type parameter definition (e.g., `class Box<T super Number>` is invalid).
- Reading from a `? super T` collection and expecting a specific type.

#### 6️⃣ Interview Q&A (High Yield)
- **Q: When to use `? super T`?** A: When your method acts as a **consumer**—it writes/inserts objects of type `T` into a collection.
- **Q: Can you add a `Dog` to a `List<? super Animal>` if `Dog extends Animal`?** A: Yes, because `Dog` is a subtype of `Animal`, and `?` is a supertype of `Animal`.

### ⚡ Wildcards — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- An unknown type represented by `?`.
- Used in method signatures and variable declarations to provide flexibility.
- Enables subtyping relationships for generic types.

#### 2️⃣ Must-Remember Points
- `?` means "some specific, but unknown, type".
- `List<?>` is a supertype of any parameterized `List` (e.g., `List<String>`, `List<Integer>`).
- Cannot add any element (except `null`) to a collection declared with `?`.
- You can read from it, but the type comes out as `Object`.

#### 3️⃣ Key Code Patterns (Java)
```java
// Method that prints any list
public void printAll(List<?> list) {
    for (Object obj : list) System.out.println(obj);
    // list.add(new Object()); // COMPILE ERROR - unknown type
    list.add(null); // Only null is allowed
}
```

#### 5️⃣ Common Interview Traps
- Trying to use a wildcard in a `new` expression (`new ArrayList<?>()` is invalid).
- Using wildcards in return types can be problematic for the caller.

#### 6️⃣ Interview Q&A (High Yield)
- **Q: What is a wildcard?** A: A placeholder for an unknown type, written as `?`, used to create flexible APIs.
- **Q: Can you add a `String` to a `List<?>`?** A: No, because the compiler doesn't know if `?` is `String` or something else. Only `null` can be added.

### ⚡ Unbounded Wildcards (<?>) — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- A wildcard with no bounds (`List<?>`).
- Represents a list of some unknown type.
- Used when you only need methods that work regardless of type (like `size()`, `clear()`).

#### 2️⃣ Must-Remember Points
- Most restrictive for "write" operations (can only add `null`).
- Fully permissive for "read" operations (but returns `Object`).
- Useful for methods that operate on the structure of the collection, not its elements.

#### 3️⃣ Key Code Patterns (Java)
```java
// Classic example: checking if a list is empty
public boolean isListEmpty(List<?> list) {
    return list.isEmpty(); // Works on any List
}
```

#### 5️⃣ Common Interview Traps
- Overusing `List<?>` when `List<Object>` or a bounded wildcard is more appropriate.

#### 6️⃣ Interview Q&A (High Yield)
- **Q: When to use unbounded wildcard `<?>`?** A: When your method's implementation depends only on methods from the generic class itself (like `List.size()`), not on the type of its elements.
- **Q: Difference between `List` and `List<?>`?** A: `List` is a raw type (bypasses generic checks, unsafe). `List<?>` is a generic type with an unknown parameter (type-safe, but restrictive).

### ⚡ Bounded Wildcards (<? extends T>, <? super T>) — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- `? extends T`: The unknown type is a **subtype of T** (producer, read-only).
- `? super T`: The unknown type is a **supertype of T** (consumer, write-friendly).
- Enable flexible subtyping with generic collections following PECS.

#### 2️⃣ Must-Remember Points
- **PECS**: Producer `extends`, Consumer `super`.
- `List<? extends Number>` can be `List<Integer>`, `List<Double>`, etc. You can read `Number`s.
- `List<? super Integer>` can be `List<Integer>`, `List<Number>`, `List<Object>`. You can add `Integer`s.
- Use them in method parameters for maximum API flexibility.

#### 3️⃣ Key Code Patterns (Java)
```java
// Producer - reads items
public double sumOfList(List<? extends Number> numbers) {
    double s = 0.0;
    for (Number n : numbers) s += n.doubleValue();
    return s;
}
// Consumer - adds items
public void populate(List<? super Integer> dest) {
    dest.add(100);
}
```

#### 5️⃣ Common Interview Traps
- Using `? extends` when you need to add (compiler error).
- Using `? super` when you need to read specific types (only `Object` is safe).

#### 6️⃣ Interview Q&A (High Yield)
| Scenario | Use |
| :--- | :--- |
| Need to iterate/read from collection | `? extends T` |
| Need to add objects to collection | `? super T` |
| Need both read and write | Use exact type parameter `<T>` |
- **Q: Explain PECS with an example.** A: For a method that copies from a source list to a destination list: `void copy(List<? extends T> src, List<? super T> dest)`. `src` produces `T`s (use `extends`), `dest` consumes `T`s (use `super`).

### ⚡ Generics with Collections — Fast Revision

#### 1️⃣ Core Idea (In 3–4 Lines)
- The primary use case for generics in Java.
- All core collection interfaces and classes (`List`, `Set`, `Map`, `Queue`) are generic.
- Ensures type-safe storage and retrieval of objects from collections.

#### 2️⃣ Must-Remember Points
- `Collection<E>`, `List<E>`, `Set<E>`, `Map<K,V>`, `Iterator<E>`, `Comparable<T>`, `Comparator<T>` are generic.
- Use diamond operator for brevity: `new HashMap<>()`.
- Collections using generics prevent adding incompatible types at compile time.
- Raw collections interoperate with generic ones (with warnings).

#### 3️⃣ Key Code Patterns (Java)
```java
// Typical generic collection usage
List<String> names = new ArrayList<>();
names.add("Alice"); // OK
// names.add(42); // Compile-time error
Map<Integer, String> map = new HashMap<>();
map.put(1, "One");
// Iterators are also generic
for (Iterator<String> it = names.iterator(); it.hasNext(); ) {
    String name = it.next(); // No cast
}
```

#### 5️⃣ Common Interview Traps
- Creating a collection of raw types and assigning it to a generic reference (causes warnings).
- Using `Collections.checkedCollection()` for runtime type checking if mixing raw and generic code.

#### 6️⃣ Interview Q&A (High Yield)
- **Q: Why are generics crucial for collections?** A: They make collections type-safe, eliminating runtime `ClassCastException` when retrieving elements.
- **Q: Can you create an array of generic type, like `List<String>[]`?** A: Yes, but it's tricky and generates a generic array creation warning. Usually discouraged; use `List<List<String>>` instead.

## 🚀 Final Java Full-Stack Interview Rapid Revision
**Top Do’s & Don’ts:**
- **DO** use PECS (`? extends` for producers, `? super` for consumers) in method signatures for flexible APIs.
- **DO** use the diamond operator `<>` for type inference.
- **DON'T** use raw types (e.g., `List`) in new code—they bypass generic checks.
- **DON'T** forget that generics are compile-time only (type erasure).

**Golden Rules:**
1. **Type Safety First:** Generics move type errors from runtime to compile-time.
2. **PECS:** Remember "Producer Extends, Consumer Super" for wildcards.
3. **No Primitive Types:** Generics work only with reference types.
4. **Erasure is Real:** You cannot use `instanceof` or `new` with a type parameter `T`.

**Last-Minute Reminders:**
- `List<Object>` and `List<String>` are **not** related by inheritance.
- `List<?>` is a supertype of any `List<SpecificType>`.
- You can only add `null` to a `List<?>`.

**Things Interviewers LOVE to Ask:**
1. Difference between `List<?>` and `List<Object>`.
2. Explain PECS with a `copy` method example.
3. What is type erasure?
4. Why can't you have `List<int>`?
5. Can a generic class extend `Throwable`? (No!)
